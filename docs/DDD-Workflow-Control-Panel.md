# DDD Workflow 控制面板

## 人工里程碑的阅读格式

每次 prepare 的 phaseRequiredOutcomes 只列当前阶段拥有章节的专业产物：I 为端到端业务事件流与边界线索，II 为子域、上下文及用例，III 为规则与模型候选，IV 为聚合根、实体、值对象和服务/持久化设计，V 为切片交付计划，VI 为实际交付证据。候选与定稿、计划与结果不得混淆。不适用项需说明业务理由，而不是编造对象。

门禁采用有限放宽：非空摘要不足建议字数、正文长度和业务概念词面未命中只提示，不阻塞。空正文、未完成必需章节、阶段越界、未决决策授权、兼容约束和工程证据仍按原机制检查。阶段专业性通过明确产物要求、现有语义校验与人工审核共同保证；关键词检查不被当作语义理解的替代。

新生成的六份罗马数字文档统一按“本阶段结论、分析范围与依据、阶段分析、需要你确认的事项、补充依据”组织。阶段分析仍保留各阶段自己的专业内容，不改变三条工作流、阶段权限和审批门禁。关键章节使用业务问题作标题，专业名称保留供追踪；来源阶段的链接集中在文末，不再穿插正文。

调度器要求阶段正文先给具体业务结论，再说明场景、理由与取舍，区分事实、建议和未知。运行时只做确定性排版，不替模型编造结论或合并相互矛盾的判断。文档可读性仍需要真实业务评审，格式测试不代表业务内容必然优秀。历史文档保持可读可审核，不批量改写；新总结采用新格式。

输入 `/ddd-workflow`，直接进入当前项目的全屏 TUI 控制面板，不需要命令参数。浏览面板不调用模型，也不会把历史文档注入模型上下文。

面板审核回传只显示简短业务消息，例如“修改里程碑 I：事件流转还不够明确”。工作流标识、审核时间和工具指令不再拼进用户发言，未回答的决策问题也不发送。插件通过消息 ID 与持久化审核记录恢复关联，在后台提供已保存审核的上下文，并阻止本轮重复调用 review。过期审核消息只允许查询状态。历史消息不回写修改。

聊天入口显示“▶ 展开聊天记录 / ▼ 收起聊天记录”，支持独立刷新。用户与助手消息逐条显示角色、时间和来源会话。普通面板刷新保留当前聊天展开状态，切换工作流或里程碑才清除；重新展开复用缓存，刷新按钮主动重新读取。

聊天按里程碑时间范围筛选，同时补回范围内助手消息的真实 parentID 对应用户 prompt（例如启动消息早于工作流创建时间）。补回消息仍按原时间排序，不扩大窗口、不猜测邻近消息；同一用户请求跨越多个里程碑时，可作为相关回复的上下文重复显示。原会话被删除时无法恢复其原文。

## 可以做什么

界面支持中文和 English，共用同一工作流状态。优先读取宿主暴露的 `locale` / `language`，否则依次读取进程的 `LC_ALL`、`LC_MESSAGES`、`LANGUAGE`、`LANG`，再回退到系统界面语言；Windows 使用 `Get-UICulture`，其他系统使用运行时区域设置。中文区域使用中文，其余区域回退英文。`C` / `POSIX` 不视为用户语言选择。

当前 OpenCode 1.18.18 SDK 没有专用 locale API，因此宿主配置字段仅作兼容检测，不向配置写入新字段。系统语言变更后重启宿主生效；宿主如果在运行中更新语言字段，面板刷新时会同步。SDK 内置弹窗的固定确认/取消控件仍由宿主控制，插件本地化其标题、提示和业务选项标记。业务文档、模型内容、用户反馈与底层原始错误不自动翻译。

布局只保留工作流列表、六个阶段、连续阅读区和审核操作，审核记录默认收起。不重复显示正文的整组派生卡片，不展示内部阶段路径；明确的事件关系仍可辅助阅读。这次调整不包含浏览器图文预览或 Mermaid 图片渲染。

- 浏览当前项目的新增功能、重构、新建系统流程，包含活动 change 和历史归档。
- 按状态、类型或关键词筛选，查看当前阶段、下一步要求和人工批准进度。
- 切换六个人工里程碑，在同一连续页面阅读结论、待确认事项、图示和完整内容；审核记录默认收起。
- 对当前可审核的里程碑批准、要求修改或拒绝。审核仍调用原有工作流引擎，不直接修改状态文件。
- 自动刷新文件变化，保留当前项目的筛选与选择。返回时恢复进入面板前的会话页面。
- 选中工作流后，点击“关联会话”或按 `s`，从该工作流的执行会话列表中选择跳转。列表显示标题、更新时间及当前执行会话标记；不可访问、已删除或属于其他项目的记录不可选择。查看会话不发送消息、不启动模型、不改变审核回传目标。

执行工具绑定会话时，保留 `runtimeSessionIds` 历史列表，`runtimeSessionId` 仍代表当前执行及审核回传目标。旧版只有后者时兼容显示一个会话，不扫描无关会话或推测已丢失的历史关联。没有关联记录时会显示说明。关联信息随原工作流状态保存和归档，不建立第二套工作流状态。

## 六个里程碑如何展示

| 里程碑 | 内容 |
| --- | --- |
| I 战略事件风暴 | 明确记录的事件关系、异常、时间约束、热点和边界线索 |
| II 战略设计 | 子域、限界上下文、上下文关系、工程承载和用例卡片 |
| III 战术事件风暴 | 上下文内事件关系、失败路径、规则和模型候选 |
| IV 战术设计 | 领域模型、应用服务、领域交互、分层和模型合同 |
| V 交付计划 | 切片依赖、业务结果、消费者、验收、测试和回滚计划 |
| VI 最终验收 | 业务验收、模型一致性、测试运行、Git、回滚和 OpenSpec 完成证据 |

可视化是对已提交资料的只读投影，不会让模型重新推测业务关系。新里程碑在状态保存事务中把已校验正式文档编译为结构化投影，面板直接读取投影；未发生变化的检查点不会重复生成。当前支持 Mermaid flowchart 中明确的方括号节点与箭头，以终端节点框和连线展示；保留原始图文本以免丢失分组或不支持的语法。Markdown 表格按原列名转换为卡片。旧流程没有投影时允许确定性恢复明确的图关系，复杂图及旧版非标准章节可在「正文」阅读。

投影包含来源检查点、稳定节点 ID、关系、成熟度、待决事项及证据引用。在「历史」中可以打开不同投影版本。每次先写不可变投影，再由原子状态保存发布引用；未发布的文件不会进入面板。正式文档与投影不一致时显示异常并禁止审核，不会重新推测一张图掩盖冲突。这是对现有文件事务的扩展，并不宣称跨多个文件具备数据库级事务原子性。

人类批准设计不等于已经实现或测试通过。切片的“已实施”来自引擎完成记录，测试结果来自正式验收证据；面板不会把计划提升为验证结果。

## 操作

| 操作 | 快捷键 |
| --- | --- |
| 选择 Workflow | ↑ / ↓ |
| 切换里程碑 | ← / → |
| 展开或收起审核记录 | 页面底部按钮 |
| 搜索、筛选状态、筛选类型 | `/`、`f`、`t` |
| 选择关联会话并跳转 | `s` |
| 刷新、滚动正文 | `r`、PgUp / PgDn |
| 批准、要求修改、拒绝 | `a`、`e`、`x` |
| 返回原页面 | Esc |

按钮也支持鼠标操作。批准前必须明确选择未决事项的选项，推荐项不会自动批准。要求修改和拒绝必须填写原因。审核提交前若文档或状态已变化，需要刷新并重新确认。归档、旧版记录、非当前里程碑和一致性异常记录只读。

审核成功后，将结果发送到工作流 `runtimeSessionId` 绑定的原会话并返回该会话。批准会继续到下一个人工检查点或阻塞处；要求修改会携带反馈进入状态机允许的修订阶段；拒绝通过 `noReply` 仅同步消息，不启动模型。消息明确要求不得再次执行同一审核。

发送前验证会话存在、项目目录一致、会话未归档且空闲。没有绑定、会话忙碌或发送失败时，审核结果仍然有效，面板提示“审核已保存，但未能同步”。使用正文底部的“同步审核结果到原会话”重试；此按钮仅发送消息，不再次批准。消息 ID 根据检查点及审核记录固定生成，重试先检查原会话已有消息，发现已发送就不重复发送。工作流进入后续阶段后，不再补发旧审核的继续指令。网络异常后不进行盲目自动重试。

不再设置可视化、结论、决策、正文、历史五个分页。本文所说的正文指单页中的“里程碑完整内容”，历史指底部可展开的审核记录。内部步骤已完成但正式文档尚未发布时显示“正在生成”，后续里程碑显示“尚未开始”；已发布文档意外丢失、路径越界等仍视为真实异常并禁止审核。

鼠标按钮在左键按下并于按钮内松开后才执行，弹窗在该次鼠标事件分发结束后打开，避免松开事件被新弹窗当作外部点击。快捷键保持原行为。

点击批准后，如果里程碑记录了未决业务问题，会依次显示“批准前确认 1/N”等选择页。选项来自该里程碑的 `decisionItems.options`，不是批准等级；推荐标记来自 `recommendationId`，不会自动生成或自动批准。未标推荐时会明确说明。最后一页展示问题和所选方案的中文名称，用户再次确认后才提交审核。没有未决问题时直接进入最终确认。

## 数据来源与兼容性

只扫描当前项目以下位置，不建立第二套工作流状态，也不迁移旧文件：

```text
openspec/changes/<change>/ddd/
openspec/changes/archive/<archive-change>/ddd/
  .ddd/workflow-state.json       当前阶段和人工审核记录
  I-...md 至 VI-...md            正式里程碑内容
  model-contract.json           已有模型合同（如存在）
  .ddd/delivery/plan.json        已有交付计划（如存在）
  .ddd/dashboard/<罗马数字>/    已发布投影的不可变版本
```

OpenSpec `tasks.md` 从所属 change 读取。损坏记录、重复 ID、归档与状态不一致会显示告警；一个坏记录不会遮蔽其他正常记录。路径读取限制在实际项目/change 内。旧版独立 `review` 字段兼容展示，但不允许通过面板修改旧版流程。

## 宿主要求与入口

服务端入口仍为 `dist/index.js`，新增原生 TUI 入口为包导出的 `./tui`，对应 `dist/tui.js`。宿主必须支持加载 TUI 插件及 Route、keymap、Dialog API。开发依赖为 OpenCode Plugin SDK 1.18.18、OpenTUI 0.4.5、Solid 1.9.12。

不支持 TUI 插件加载的 Mobile Coder 版本不会因为安装服务端插件就自动出现面板；这需要宿主本身提供对应 SDK 能力。面板不修改宿主源码，也不通过 MCP 或 LLM Slash 模板模拟原生界面。

## OpenCode 完整安装

在插件源码目录执行：

```powershell
npm ci
npm run build
npm run install:opencode -- --check
npm run install:opencode
```

安装命令同时配置服务端原生工具入口、TUI 插件、17 个专业 Skill，以及 `/ddd`、`/ddd-code`、`/ddd-status`。`/ddd-workflow` 由原生 TUI 注册，不生成让模型执行的同名 Markdown 命令。默认安装到 `$XDG_CONFIG_HOME/opencode`，未设置时为 `~/.config/opencode`；可用 `--config-root <目录>` 指定隔离配置。

安装保留其他插件、设置和 JSONC 注释；覆盖前保存到配置目录的 `.ddd-install-backups/<时间戳>/`，失败时回滚已写文件，重复执行不重复注册。`--check` 只显示待更新文件，不落盘。若同名 JSON 和 JSONC 同时存在，则停止并要求先明确配置来源。

这是本地路径安装，不复制整个运行时；必须保留插件目录和 npm 依赖。OpenSpec CLI 随插件依赖提供。完成后退出并重新启动 OpenCode，输入 `/ddd-workflow` 打开控制面板。已在 OpenCode 1.18.18 验证；其他宿主是否支持原生 TUI 取决于其 SDK。

# 自动会话关联与续跑

## 简化后的主状态与聊天

工作流列表只区分已完成（生命周期完成并归档）和未完成。里程碑条将已批准映射为已完成；仅第一个未完成的里程碑显示待开始或执行中，后续里程碑留空。执行中表示该里程碑已开始但未完成，不表示模型持续在线。审核、修改、阻塞和归档仍由原状态机控制，放在当前处理事项中解释，不作为里程碑主状态。

点击某里程碑的聊天记录，分页读取所有已关联会话的用户和助手可见消息，以消息创建时间筛选并合并排序；相同时间按会话 ID 和消息 ID 稳定排序。没有工具调用的讨论、修改要求和闲聊同样收录，消息标注时间及来源会话。不读取内部推理，不展示工具输出。

时间边界取自工作流创建、检查点提交、人工审核和当前 prepare 时间。批准后从审核时间开始归入下一里程碑，VI 保持到流程结束；旧检查点保留时，回访里程碑可以形成多个时间段。范围为左闭右开，避免边界重复。流程结束后的消息不继续收录。时间归属不代表业务语义归属：进入 II 后讨论 I 的修改仍落在 II 的时间段；不由模型猜测重分类。旧记录缺少起始或回退时间时只能覆盖现有时间证据，不能保证还原缺失区间。

不再生成或依赖 `.ddd/chat-links.json` 工具调用索引，已有文件保留但不消费。原文仍存储在宿主会话中，此视图不代替备份。会话读取失败时展示警告并保留其他会话结果；没有会话关联或可用时间范围时明确提示。

## 审核与执行分开展示

上一里程碑批准并不表示下一阶段已经执行。面板根据现有状态机派生“待执行”：当前流程允许继续、上一检查点已批准，且下一阶段尚无 prepare 记录。上一里程碑保持“已批准”，下一目标标为“待执行”，详情顶部显示执行提示，底部提供“执行下一阶段”入口；状态筛选也支持“待执行”。

该入口复用续跑会话选择、忙碌检查和生命周期门禁，不重复 review，不直接修改阶段。prepare 后显示形成中；正式检查点形成后才显示待审核。最终验收通过后仍是待归档，不误标为下一里程碑待执行。这里展示的是持久化工作进度，不据此声称模型此刻正在运行；是否忙碌由续跑发送前的宿主状态检查决定。

控制面板提供两个独立入口：

- **执行会话（s）**：只列出实际记录过的执行会话，选择后仅跳转，不发送消息、不修改关联。
- **继续（c）**：选择当前会话（默认）、上次执行会话、新建会话或当前目录的其他主会话。当前会话指打开面板前的会话；从首页进入时该选项不可用。

选择目标本身不关联。面板发送指定工作流的续跑请求，生命周期工具实际推进时自动记录执行会话；若只是读取待审核结果而未推进，不改变原执行会话。续跑请求明确禁止自动批准。工作流状态仍属于 change，不随会话移动。

发送前重新读取工作流，阻止归档、结束、旧版只读或不一致的工作流续跑；检查目标和已记录的执行会话是否忙碌，不中断它们。其他会话列表排除不同目录、归档和子代理会话。该检查基于宿主当时的会话状态，并非跨进程事务锁。网络失败不自动重试，需先查看目标会话是否收到请求，避免重复触发。

在会话中初始化 DDD 工作流会自动记录该会话，不需要手动关联。控制面板的关联会话列表只用于选择并跳转到已记录的执行会话。

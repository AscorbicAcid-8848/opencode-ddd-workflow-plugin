# DDD Workflow 控制面板

输入 `/ddd-workflow`，直接进入当前项目的全屏 TUI 控制面板，不需要命令参数。浏览面板不调用模型，也不会把历史文档注入模型上下文。

## 可以做什么

- 浏览当前项目的新增功能、重构、新建系统流程，包含活动 change 和历史归档。
- 按状态、类型或关键词筛选，查看当前阶段、下一步要求和人工批准进度。
- 切换六个人工里程碑，阅读可视化、结论、决策、正式文档和提交历史。
- 对当前可审核的里程碑批准、要求修改或拒绝。审核仍调用原有工作流引擎，不直接修改状态文件。
- 自动刷新文件变化，保留当前项目的筛选与选择。返回时恢复进入面板前的会话页面。

## 六个里程碑如何展示

| 里程碑 | 内容 |
| --- | --- |
| I 战略事件风暴 | 明确记录的事件关系、异常、时间约束、热点和边界线索 |
| II 战略设计 | 子域、限界上下文、上下文关系、工程承载和用例卡片 |
| III 战术事件风暴 | 上下文内事件关系、失败路径、规则和模型候选 |
| IV 战术设计 | 领域模型、应用服务、领域交互、分层和模型合同 |
| V 交付计划 | 切片依赖、业务结果、消费者、验收、测试和回滚计划 |
| VI 最终验收 | 业务验收、模型一致性、测试运行、Git、回滚和 OpenSpec 完成证据 |

可视化是对已提交资料的只读投影，不会让模型重新推测业务关系。新里程碑在状态保存事务中把已校验正式文档编译为结构化投影，面板直接读取投影；未发生变化的检查点不会重复生成。当前支持 Mermaid flowchart 中明确的方括号节点与箭头，以终端节点框和连线展示；保留原始图文本以免丢失分组或不支持的语法。Markdown 表格按原列名转换为卡片。旧流程没有投影时允许确定性恢复明确的图关系，复杂图及旧版非标准章节可在「正文」阅读。

投影包含来源检查点、稳定节点 ID、关系、成熟度、待决事项及证据引用。在「历史」中可以打开不同投影版本。每次先写不可变投影，再由原子状态保存发布引用；未发布的文件不会进入面板。正式文档与投影不一致时显示异常并禁止审核，不会重新推测一张图掩盖冲突。这是对现有文件事务的扩展，并不宣称跨多个文件具备数据库级事务原子性。

人类批准设计不等于已经实现或测试通过。切片的“已实施”来自引擎完成记录，测试结果来自正式验收证据；面板不会把计划提升为验证结果。

## 操作

| 操作 | 快捷键 |
| --- | --- |
| 选择 Workflow | ↑ / ↓ |
| 切换里程碑 | ← / → |
| 切换可视化、结论、决策、正文、历史 | Tab |
| 搜索、筛选状态、筛选类型 | `/`、`f`、`t` |
| 刷新、滚动正文 | `r`、PgUp / PgDn |
| 批准、要求修改、拒绝 | `a`、`e`、`x` |
| 返回原页面 | Esc |

按钮也支持鼠标操作。批准前必须明确选择未决事项的选项，推荐项不会自动批准。要求修改和拒绝必须填写原因。审核提交前若文档或状态已变化，需要刷新并重新确认。归档、旧版记录、非当前里程碑和一致性异常记录只读。

审核只记录决定，不会自动启动模型继续研发。完成审核后返回原会话继续。

## 数据来源与兼容性

只扫描当前项目以下位置，不建立第二套工作流状态，也不迁移旧文件：

```text
openspec/changes/<change>/ddd/
openspec/changes/archive/<archive-change>/ddd/
  .ddd/workflow-state.json       当前阶段和人工审核记录
  I-...md 至 VI-...md            正式里程碑内容
  model-contract.json           已有模型合同（如存在）
  .ddd/delivery/plan.json        已有交付计划（如存在）
  .ddd/dashboard/<罗马数字>/    已发布投影的不可变版本
```

OpenSpec `tasks.md` 从所属 change 读取。损坏记录、重复 ID、归档与状态不一致会显示告警；一个坏记录不会遮蔽其他正常记录。路径读取限制在实际项目/change 内。旧版独立 `review` 字段兼容展示，但不允许通过面板修改旧版流程。

## 宿主要求与入口

服务端入口仍为 `dist/index.js`，新增原生 TUI 入口为包导出的 `./tui`，对应 `dist/tui.js`。宿主必须支持加载 TUI 插件及 Route、keymap、Dialog API。开发依赖为 OpenCode Plugin SDK 1.18.18、OpenTUI 0.4.5、Solid 1.9.12。

不支持 TUI 插件加载的 Mobile Coder 版本不会因为安装服务端插件就自动出现面板；这需要宿主本身提供对应 SDK 能力。面板不修改宿主源码，也不通过 MCP 或 LLM Slash 模板模拟原生界面。

## OpenCode 完整安装

在插件源码目录执行：

```powershell
npm ci
npm run build
npm run install:opencode -- --check
npm run install:opencode
```

安装命令同时配置服务端原生工具入口、TUI 插件、17 个专业 Skill，以及 `/ddd`、`/ddd-code`、`/ddd-status`。`/ddd-workflow` 由原生 TUI 注册，不生成让模型执行的同名 Markdown 命令。默认安装到 `$XDG_CONFIG_HOME/opencode`，未设置时为 `~/.config/opencode`；可用 `--config-root <目录>` 指定隔离配置。

安装保留其他插件、设置和 JSONC 注释；覆盖前保存到配置目录的 `.ddd-install-backups/<时间戳>/`，失败时回滚已写文件，重复执行不重复注册。`--check` 只显示待更新文件，不落盘。若同名 JSON 和 JSONC 同时存在，则停止并要求先明确配置来源。

这是本地路径安装，不复制整个运行时；必须保留插件目录和 npm 依赖。OpenSpec CLI 随插件依赖提供。完成后退出并重新启动 OpenCode，输入 `/ddd-workflow` 打开控制面板。已在 OpenCode 1.18.18 验证；其他宿主是否支持原生 TUI 取决于其 SDK。

## 开发与验证命令

```text
src/tui.ts                      原生命令、路由、渲染和对话框
src/dashboard/model.ts          项目扫描、历史兼容和只读投影
src/dashboard/views.ts          六里程碑卡片与显式图关系
src/dashboard/projections.ts    状态事务中的投影编译和版本保存
src/dashboard/actions.ts        审核前置检查与既有引擎调用
tests/dashboard.test.mjs        扫描、兼容、安全和审核回归测试
tests/tui-render.bun.mjs         真实 OpenTUI 渲染器与交互冒烟测试
```

运行 `npm test` 检查构建与回归，运行 `npm run test:tui` 检查原生渲染和键盘交互。后者使用真实 OpenTUI 渲染器，但 SDK 宿主对象为测试替身，不等同于真实 Mobile Coder 全生命周期验收。

已补充 OpenCode 1.18.18 的真实终端实测，覆盖命令、页面、筛选、里程碑阅读、事件图和测试副本上的修改反馈，详见[真实宿主测试记录](reports/2026-09-07-opencode-dashboard-live.md)。命令注册必须使用当前宿主 keymap 的 `namespace: "palette"`、`slashName` 字段，不能与普通命令适配器的 `slash` 字段混用。

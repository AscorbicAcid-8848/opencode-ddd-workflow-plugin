# 生命周期约束简化

## 原则

模型解释业务含义并提出决策；状态机验证合法顺序、结构化授权和标识；实际证据验证交付结果。正则可以检查格式或提示疑点，不能证明业务含义。语义告警不会自动批准里程碑。

## 本次修改

| 原问题 | 调整 |
|---|---|
| 反馈关键词决定回退阶段 | 移除反馈正则，返回当前里程碑合法 writer 集合，由模型解释反馈后选择。未授权跨里程碑回退不会自动开放。 |
| 现状只能消费一次证据包 | 允许定向 read/glob/grep；补充代码引用检查实际文件及行范围。证据包不是完整仓库知识的上限。 |
| 固定 16 次读取、10 次 Shell | 删除次数硬限制和下载关键词拦截；编码仍须进入合法实现阶段，宿主权限仍有效。 |
| 自然语言触发硬门禁 | 阶段语义、业务扩展、未决事项措辞、外部系统推断、兼容性词面匹配改为 warning。 |
| 强制 ORM 双模型和四层目录 | 改为架构复核建议，不把某一种目录布局当作 DDD 的唯一实现。 |
| 根据任意工具参数识别 DDD | 只识别注册的 ddd_lifecycle；只有成功的 prepare 结果更新阶段访问状态。 |
| 拒绝写入时偷偷改目标路径 | 取消参数重写，显式报权限错误。依赖宿主正确传播 Hook 异常，不声称这是操作系统级沙箱。 |
| 未注册的章节工具残留 | 删除 submitSectionTool、finalizeStageTool 及无调用辅助代码。 |
| 编码命令隐式批准 V | review 必须传显式 decision/reviewer，命令本身不替代审核授权；统一 status 指导。 |

Skill 同步遵循上述约束：允许相关证据补读、必要工程验证及简短进度说明，不要求凑字数或调用配额。

## 保留的硬约束

- 合法阶段、当前人工审核点、切片依赖和批准范围。
- 正式文档经生命周期发布；结构化字段、标识和引用有效。
- 真实测试、Git、模型覆盖和 OpenSpec 归档前置条件。
- 声明不存在的结构化事实需要相应证据，不能由代码词未命中推断整个业务不存在。

## 测试调整

删除八个以固定证据包、下载关键词或特定语句阻塞为目标的过度约束测试；其余相关断言改为验证 warning、合法阶段集合、显式拒绝以及状态不被错误入参更新。新增六个回归测试覆盖补充取证、超出旧次数限制的合法调用、失败 prepare、不相关工具、架构表达和实际引用。

自动化测试不代表真实模型已理解 DDD；本次没有重新执行付费模型全生命周期评测。Hook 测试模拟 SDK 返回值，不执行其中示例 Shell 命令。

2026-09-09 验证：`npm test` 222/222 通过；4 个修改的 Skill 通过 `quick_validate.py` 校验；`git diff --check` 通过。Windows Skill 校验使用 Python UTF-8 模式。

## 适配边界

本次针对当前 OpenCode/Mobile 原生插件。保留的 MCP 兼容入口没有宿主 chat.message 事件，不能据此声称它具有同等的逐轮用户意图绑定；没有把模型自报的引用冒充宿主验证。该入口的授权统一需单独对接实际调用宿主，不能仅靠开放 intent 参数解决。

人工修改目前只开放当前里程碑拥有的阶段。若需推翻此前已经批准的里程碑，应明确授权并实现下游失效处理，不能因为一句反馈命中关键词而隐式回退。

# 对话意图与工作流授权

普通对话不再使用正则匹配句首“批准”“继续”等词。当前模型根据用户完整语义提交一次 intent，对话 hook 提供当前消息 ID；input 包含 messageID、intent、quote、continueAfterReview。intent 可为 query、clarify、start、continue、approve、revise、reject。

这不是单独的分类模型或另一条业务工作流，而是同一个模型的一次轻量工具调用。身份和引用检查只验证声明来源，不证明语义一定正确。问题、引用、否定、假设以及含糊意见由模型辨认；无法确定授权时应澄清。模型仍可能误判，需通过真实会话评测持续验证，而不是宣称绝对准确。

程序职责：

- 普通用户新消息默认 pending，status 可读，未声明意图不能写入或运行工程命令。
- 引用须来自当前消息，过期消息不能重用；本轮声明不可自行升级。
- 继续授权绑定一个工作流；approve/revise/reject 绑定当前检查点，成功后不可重复审核下一个检查点。
- 审核后是否继续取决于 continueAfterReview。仅批准不继续会返回停止；批准并继续可以连续执行到下个人工检查点。
- 新用户消息重置本轮授权；普通询问不会沿用上一轮的执行权限。
- /ddd-status 为程序确定的只读入口，模型不得提升权限。面板审核通过已保存记录验证，不重复调用 intent/review。
- 原有阶段顺序、领域范围、业务决策及真实证据门禁仍负责执行合法性。

此适配在 OpenCode 的 chat.message 与生命周期工具入口生效。直接调用核心引擎的测试和其他非对话客户端仍使用自己的授权边界；不应把内部引擎函数当作面对不可信调用方的接口。当前不会持久化一套新工作流状态，意图工具输入已在宿主会话历史中留痕。

自动测试验证意图协议、当前消息绑定、只读保护、单检查点授权，以及 intent → review → prepare 的完整工具路径；它不替代真实模型对中文表达的准确率评测。
